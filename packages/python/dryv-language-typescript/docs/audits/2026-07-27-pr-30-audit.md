## Findings

### TS-AUDIT-001 — Direct option construction is not runtime type-safe

**Severity:** medium correctness issue

`TypeScriptTargetOptions.__post_init__()` validates package-name content and alias ordering, but it does not verify that policy fields are instances of their declared enums.

For example:

```python
TypeScriptTargetOptions(extension_policy="omitTypeScript")
```

is accepted even though `extension_policy` is a plain string. Later code uses identity comparisons:

```python
options.extension_policy is TypeScriptExtensionPolicy.OMIT_TYPESCRIPT
```

The comparison is false, so TypeScript suffixes are unexpectedly preserved. Similar problems apply to reserved-word, Unicode, and index policies. A non-string `package_name` can also raise an uncontrolled `TypeError` inside the regular expression instead of a stable validation error.

**Required fix:** validate exact enum and scalar types in `__post_init__()`, or normalize through a single strict constructor. Direct construction and `from_mapping()` must have equivalent validation.

Add tests for raw strings, integers, booleans, invalid alias collection types, and invalid package-name types.

### TS-AUDIT-002 — Release gates were recorded as open but the PR was merged

**Severity:** high release-process issue

The package progress record says the exact repository-core suite, Ruff, `python -m build`, and real core-wheel installation were not verified. The task remains at `review` and must not be marked release-complete until those exact commands pass.

### TS-AUDIT-003 — Wheel-content tests can skip in the normal pytest phase

**Severity:** medium verification gap

Distribution tests skip wheel/sdist inspection when `dist/` does not already contain artifacts. The documented command order runs pytest before `python -m build`, so those tests may report skips and never inspect the newly built artifacts.

**Required fix:** add an explicit post-build verification command/test, or have distribution tests build into a temporary directory before inspection. Do not rely on stale pre-existing `dist/` files.

### TS-AUDIT-005 — Package and plugin versions have separate literals

**Severity:** low maintenance issue

`pyproject.toml` uses `0.1.0a1`, while the plugin descriptor independently hard-codes `0.1.0-alpha.1`. These are intended PEP 440/SemVer equivalents but can drift.

**Suggested fix:** define one package semantic-version constant and test its relationship to installed metadata.
