# PR #29 audit — `codepotg-openapi`

**Audit date:** 2026-07-27  
**PR:** #29  
**Merged head:** `5430d03c9e167ffcc9977dac0efdf73a7267af5c`  
**Merge commit:** `62de434e8911bd2ae7ed32893f6b0eaab79a9c8a`  
**Audit method:** merged-code, package-tree, public-contract, tests, and task-ledger review. Commands were not independently rerun in this environment.

## Verdict

**Implementation quality of individual subsystems:** promising.  
**Architecture direction:** mostly correct.  
**Package usability:** **broken**.  
**Release readiness:** **not ready**.  
**Fix urgency:** critical.

PR #29 merged useful loader, parser, reference, schema, group, and operation-normalization foundations. It did not merge the adapter facade that connects those parts to the advertised source-adapter entry point. The installed distribution cannot load its plugin factory successfully.

## Critical release blocker

### OPENAPI-AUDIT-001 — Advertised entry point imports a missing module

**Severity:** critical

`codepotg_openapi.plugin.create_plugin()` imports:

```python
from .adapter import OpenApiSourceAdapter
```

but this merged package contains no:

```text
src/codepotg_openapi/adapter.py
```

`codepotg_openapi.__getattr__()` also imports the same missing module.

Consequences:

- `create_plugin()` fails;
- entry-point discovery fails when the factory is invoked;
- `from codepotg_openapi import OpenApiSourceAdapter` fails;
- the package cannot satisfy `codepotg.ports.SourceAdapter`;
- no caller can obtain a final `SourceAdapterResult`.

This should have been caught by import-smoke, entry-point, conformance, and isolated-wheel tests. Those test classes were not merged.

## Other high-severity findings

### OPENAPI-AUDIT-002 — There is no top-level normalization/contract orchestration

**Severity:** high

The merged code contains focused helpers but no production path that performs:

```text
load root
→ parse
→ resolve references
→ normalize schemas/groups/operations
→ construct Contract
→ run core validation
→ calculate final digest
→ return SourceAdapterResult
```

There is no merged adapter, normalizer facade, or final contract-result integration.

### OPENAPI-AUDIT-003 — README claims implementation that is absent

**Severity:** high documentation and release issue

The README says the package:

- decodes typed `x-codegen` version 2 metadata;
- returns the immutable closed kernel;
- has support documentation under `docs/support/README.md`;
- has benchmarks under `benchmarks/README.md`.

The merged PR contains no `x_codegen` implementation package, no support document, and no benchmark directory. The README therefore describes intended final behavior rather than merged behavior.

### OPENAPI-AUDIT-004 — Controlled loader cache is instance-scoped, not compile-session-scoped

**Severity:** high correctness/determinism/security issue

`ControlledSourceLoader` owns `_reference_cache` for the lifetime of the loader instance. If one adapter/loader instance is reused across normalization requests, external documents can remain cached across sessions.

Risks:

- stale external documents after source changes;
- host loader output from one run reused in another run;
- memory-root references collide when the same `source_id` is reused with different content;
- digest/result no longer reflects what the host loader would return for the current run;
- session isolation requirement is violated.

**Required resolution:** make reference document caching explicitly operation/session-owned, or construct a fresh controlled loader/session cache for every `normalize()` call. Add tests proving no cache state crosses calls.

### OPENAPI-AUDIT-005 — YAML aliases can create recursive or explosive conversion

**Severity:** high parser-hardening issue

`yaml.compose(..., SafeLoader)` is converted recursively by `_convert_yaml_node()` without:

- active-node cycle detection;
- maximum YAML node depth;
- maximum converted item count;
- alias expansion accounting.

A recursive alias can lead to `RecursionError` escaping the expected parser diagnostic boundary. An alias expansion graph can cause disproportionate CPU/memory work even when source bytes are bounded.

**Required resolution:** reject recursive aliases or convert with an active-node set and explicit depth/item limits. Convert `RecursionError` and limit violations into stable diagnostics. Add adversarial fixtures.

## Medium findings

### OPENAPI-AUDIT-006 — No package-level tests were merged

Only subsystem unit tests were added. Missing required areas include:

- entry-point/import smoke;
- public source-adapter conformance;
- final adapter success/failure;
- architecture/import boundaries;
- integration fixture;
- cancellation across the composed adapter;
- parse/reference-once instrumentation through the public facade;
- distribution and isolated-wheel tests;
- benchmarks.

The reported 107-test result therefore does not prove an installable working adapter.

### OPENAPI-AUDIT-007 — Task and progress ledgers were not updated

`docs/tasks/PROGRESS.md` still says implementation has not started. The master task plan still marks every task planned. This hides both the useful completed foundations and the critical missing work.

### OPENAPI-AUDIT-008 — `x-codegen` type references exist without an implementation

`NormalizationContext` type-checks against `codepotg_openapi.x_codegen.models.XCodegen`, and normalizers call `context.x_codegen.schema(...)` and `.operation(...)`, but no merged `x_codegen` package exists.

The `None` path allows standard normalization helpers to operate, but the advertised typed metadata support is not implemented.

### OPENAPI-AUDIT-009 — Referenced Path Item provenance has a root-document error path

When a resolved external Path Item is not an object, one diagnostic uses `context.root.span(path_pointer)` instead of `path_document.span(path_pointer)`. This can produce missing or incorrect provenance for the external source.

This is not the primary blocker but should be corrected with an external Path Item test.

## What was implemented well

The following foundations are useful and mostly aligned with the architecture:

- immutable typed option decoding with unknown-field rejection;
- memory/local authority controls and path containment;
- safe default denial of uncontrolled network access;
- duplicate-key-aware JSON/YAML parsing;
- source identities and YAML spans;
- canonical JSON Pointer handling;
- per-resolver reference/document indexing;
- reference depth and document-count limits;
- stable semantic ID helpers;
- substantial structural schema normalization;
- deterministic group and operation ordering;
- neutral operation inputs/outputs/failures and minimal HTTP facet construction;
- warnings for public-core blockers rather than target-specific invention;
- no TypeScript, Dart, Jinja, writer, CLI, or framework ownership in the merged implementation.

## Required fix order

1. Add the real `OpenApiSourceAdapter` and one composed normalization session.
2. Add public entry-point/import/conformance tests before any further semantic expansion.
3. Make loading/reference caches session-owned.
4. Harden YAML alias/cycle/depth/item handling.
5. Add final `Contract` construction, core validation, diagnostics, cancellation, and digest.
6. Correct README claims to match current support until later tasks land.
7. Implement typed `x-codegen` before claiming it.
8. Continue OA-009..OA-015 in coherent tested batches.
9. Add realistic fixture, benchmarks, wheel/sdist, and isolated installation.
