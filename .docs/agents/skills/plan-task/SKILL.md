# Skill: plan task

## Use when

Turning an approved requirement into implementable work for one package or app.

## Procedure

1. State the problem and evidence.
2. Identify the owning item, subsystem, dependencies, and conflicts.
3. Define scope and non-goals.
4. List required reading.
5. Declare allowed and forbidden paths.
6. State architecture constraints and compatibility impact.
7. Define observable acceptance criteria.
8. Provide exact validation commands and documentation impact.
9. Keep unresolved design work out of implementation tasks.
10. Add one short pointer to `.docs/TODO.md` only when this becomes the current repository focus.

## Output

A task file under the owning item, such as `.docs/packages/python/dryv-cli/tasks/<task>.md` or `.docs/apps/site/tasks/<task>.md`.
