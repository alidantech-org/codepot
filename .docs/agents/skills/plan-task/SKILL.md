# Skill: plan task

## Use when

Turning an approved requirement into implementable work.

## Procedure

1. State the problem and evidence.
2. Identify owner, subsystem, dependencies, and conflicts.
3. Define scope and non-goals.
4. List required reading.
5. Declare allowed and forbidden paths.
6. State architecture constraints and compatibility impact.
7. Define observable acceptance criteria.
8. Provide exact validation commands and documentation impact.
9. Set status to `ready` only when no material decision remains unresolved.

## Output

A task file using `.docs/tasks/templates/task.md`.
