## Findings

### DART-AUDIT-001 — Direct option construction is not runtime type-safe

**Severity:** medium correctness issue

`DartTargetOptions.__post_init__()` validates package-name content and `prefer_package_uris`, but it does not validate the three enum policy fields.

For example:

```python
DartTargetOptions(private_identifier_policy="requirePublic")
```

is accepted as a plain string. Later code uses enum identity comparisons, so the requested policy is silently ignored. `to_dict()` may also fail because the string has no `.value` property. A non-string `package_name` can escape as a regular-expression `TypeError` instead of a stable validation error.

**Required fix:** validate exact enum/scalar types during direct construction, or route all construction through one strict decoder. Add direct-constructor negative tests.

### DART-AUDIT-002 — Dart SDK oracle was not run

**Severity:** high release-verification gap

The package’s keyword and URI baseline is intentionally pinned to Dart, but the recorded SDK oracle was skipped because Dart was unavailable. The package cannot be called release-complete until representative fixtures are checked with a real Dart SDK.

The honest skip is correct; merging before closing the release gate was not.

### DART-AUDIT-003 — Other release gates remained open

**Severity:** high release-process issue

The exact synchronized core suite, Ruff, `python -m build`, real core-wheel installation, and real package-wheel checks remained unverified according to the package’s own progress record.

### DART-AUDIT-004 — Wheel-content tests can skip before build

**Severity:** medium verification gap

Like the TypeScript package, distribution inspection skips when `dist/` is empty, while the documented command order builds after pytest. Add a post-build verification step or build in a temporary directory from the test.
