# Choose a workflow

## Building the current Codepot direction

Use Dryv:

```text
Authoring → Runtime IR → packs → usage and generated output
```

Begin with the [Dryv overview](/docs/dryv).

## Maintaining an existing CodepotG or Node.js installation

Use the relevant [frozen package reference](/docs/packages). Changes to frozen packages require an explicit maintenance task and must not redirect the active architecture back toward those implementations.

## Evaluating the research thesis

Evaluate canonical semantics, deterministic planning, traceability, target capability reporting, pack conformance, migration experiments, and human/AI review cost. Do not treat one generated demo as proof of universal portability.
