# Documentation guide

`.docs/` is the only canonical authored documentation system.

## Ownership

- project identity and status: `.docs/project/`
- approved architecture: `.docs/architecture/`
- product documentation: `.docs/products/`
- application documentation: `.docs/apps/`
- agent rules and skills: `.docs/agents/`
- tasks and evidence: `.docs/tasks/`
- audits and decisions: `.docs/audits/` and `.docs/decisions/`
- operations: `.docs/operations/`
- selected public documentation: `.docs/public/`

The existing `.docs/plan/` and `.docs/research/` collections remain protected bodies of work until a separate approved reorganization.

## Rules

- Update the canonical document rather than creating a competing copy.
- Link to shared rules instead of repeating them.
- Label active, frozen, planned, implemented, and historical material clearly.
- Keep app and package READMEs concise.
- Validate public navigation, sources, links, redirects, and generated outputs after changes.
