# Codepot

Codepot is a TypeScript authoring and code-generation system built around three independent layers:

1. **Authoring** loads `codepotx.config.ts` and compiles user contracts into a stable JSON-safe `CompiledAuthoringArtifact`.
2. **Templating** loads `paths.yaml`, Handlebars templates, partials, raw files, helper declarations, and a validatable template-variable contract.
3. **Generation** loads `CodepotFile.yml`, combines stable artifacts, creates a deterministic plan, renders entirely in memory, and applies safe transactional writes.

The layers communicate only through shared contracts and injected ports. The runtime composes them, while the separate CLI is one replaceable frontend.

## No OpenAPI intermediate is required

Codepot contracts are the visible source of generated code. Generation consumes the stable authoring artifact directly. OpenAPI can be offered as an optional output target, but authoring does not need to become OpenAPI before templates can use it.

## Core guarantees

- Existing contracts can migrate primarily by importing Codepot APIs and `z` from `codepotx`.
- Template variables, helpers, partials, and dynamic path expressions can be listed and validated before rendering.
- Rendering completes before filesystem mutation.
- Duplicate or unsafe output paths fail during planning.
- Managed manifests allow safe stale-file cleanup without broad recursive deletion.
- Transactional tasks roll back generated bytes and manifests after required failures or cancellation.
- Events are observational and never hidden control flow.

## Packages

- `codepotx` — contracts, authoring, templating, generation, runtime, and platform adapters.
- `codepotx-cli` — the external `codepotx` command-line frontend.
- `@codepot/site` — the documentation and product website under `apps/site`.
